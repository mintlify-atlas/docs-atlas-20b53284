title: Netlist Generation

Netlist generation is the final phase of CircuitVision's pipeline, transforming detected components and topology into **SPICE-compatible netlists**. This occurs in two stages: structural netlist creation from geometric analysis, followed by AI-powered value enrichment via Google's Gemini.

## Two-Stage Process

<Steps>
  <Step title="Structural Netlist Generation">
    Creates "valueless" netlist from node topology and component types, including semantic directions from VLM
  </Step>
  <Step title="Gemini-Powered Enrichment">
    Extracts component values and verifies types using Gemini Pro Vision on the enumerated circuit image
  </Step>
</Steps>

## Stage 1: Structural Netlist

The structural netlist maps circuit topology to SPICE syntax without component values.

### Generation Algorithm

```python
# From src/analysis_pipeline.py:269-276
valueless_netlist = analyzer.generate_netlist_from_nodes(nodes)
valueless_netlist_text = '\n'.join([
    analyzer.stringify_line(line) for line in valueless_netlist
])
```

Each node from topology analysis becomes netlist entries:

```python
# Conceptual implementation
def generate_netlist_from_nodes(self, nodes):
    netlist = []
    component_counter = {}
    
    for node in nodes:
        node_id = node['id']
        
        for component in node['components']:
            comp_class = component['class']
            
            # Get SPICE prefix (R, C, L, V, etc.)
            spice_prefix = self.netlist_map[comp_class]
            
            # Generate unique component ID
            component_counter[spice_prefix] = component_counter.get(spice_prefix, 0) + 1
            comp_id = f"{spice_prefix}{component_counter[spice_prefix]}"
            
            # Determine terminal nodes
            terminals = determine_terminals(component, nodes)
            
            # Create netlist line
            netlist.append({
                'id': comp_id,
                'class': comp_class,
                'terminals': terminals,
                'value': None,  # To be filled by Gemini
                'semantic_direction': component.get('semantic_direction', 'UNKNOWN')
            })
    
    return netlist
```

### Component-to-SPICE Mapping

The `netlist_map` dictionary (`src/circuit_analyzer.py:66-102`) defines SPICE prefixes:

```python
self.netlist_map = {
    'resistor': 'R',
    'resistor.adjustable': 'R',
    'capacitor': 'C',
    'capacitor.unpolarized': 'C',
    'capacitor.polarized': 'C',
    'inductor': 'L',
    'diode': 'D',
    'diode.zener': 'D',
    'diode.light_emitting': 'D',
    'transistor.bjt': 'Q',
    'transistor.fet': 'M',
    'voltage.dc': 'V',
    'voltage.ac': 'V',
    'voltage.dependent': 'E',
    'current.dc': 'I',
    'current.dependent': 'G',
    'gnd': '0',                    # Ground is node 0 in SPICE
    'integrated_circuit': 'X',
    'operational_amplifier': 'X',
    'transformer': 'T',
    # ... additional mappings
}
```

<Note>
Subclasses (e.g., `capacitor.polarized`, `capacitor.unpolarized`) map to the same SPICE prefix but may have different value formats or polarity requirements.
</Note>

### Terminal Assignment

Component terminals are assigned based on:

1. **Connection Points**: From topology analysis, indicates which nodes the component touches
2. **Semantic Direction**: From VLM enrichment, determines terminal order for polarized components

Example for a resistor connecting nodes 1 and 3:
```spice
R1 1 3 10k
```

Example for a diode (direction matters):
```spice
D1 2 5 1N4148  ; Anode at node 2, cathode at node 5
```

### Semantic Direction Enrichment

Before netlist generation, a VLM (Gemini) analyzes component orientations:

```python
# From src/analysis_pipeline.py:139-166
can_enrich = (
    bboxes_to_enrich and
    image_for_enrichment is not None and
    hasattr(analyzer, 'gemini_client') and analyzer.gemini_client
)

if can_enrich:
    analyzer._enrich_bboxes_with_directions(
        cv2.cvtColor(image_for_enrichment, cv2.COLOR_BGR2RGB),
        bboxes_to_enrich
    )
```

This adds `semantic_direction` to each bbox:
- `LEFT_TO_RIGHT`
- `RIGHT_TO_LEFT`
- `TOP_TO_BOTTOM`
- `BOTTOM_TO_TOP`
- `UNKNOWN`

**Components Requiring Direction:**
- Voltage sources (+ and - terminals)
- Diodes (anode and cathode)
- Transistors (collector, base, emitter order)
- Polarized capacitors

<Info>
Direction enrichment occurs **before** netlist generation in `src/analysis_pipeline.py:139-166`. This ensures terminal order is correct in the structural netlist.
</Info>

**Prompt (Conceptual):**
```

1. Identify the component type (resistor, capacitor, etc.)
2. Extract the labeled value (e.g., "10kΩ", "100µF", "12V")
3. Return as structured JSON: {"1": {"type": "resistor", "value": "10k"}, ...}
```

### Netlist Fixing

The `fix_netlist` method merges Gemini's output with the structural netlist:

```python
# Conceptual implementation
def fix_netlist(self, netlist, gemini_info, bbox_ids):
    for line in netlist:
        # Find corresponding component in bbox_ids
        component_id = find_component_by_uid(line['uid'], bbox_ids)
        
        if component_id in gemini_info:
            gemini_data = gemini_info[component_id]
            
            # Update value
            if 'value' in gemini_data:
                line['value'] = parse_value(gemini_data['value'])
            
            # Verify/correct type
            if 'type' in gemini_data:
                gemini_type = normalize_type(gemini_data['type'])
                if gemini_type != line['class']:
                    logger.warning(f"Type mismatch: YOLO={line['class']}, Gemini={gemini_type}")
                    # Gemini takes precedence for certain ambiguous cases
                    line['class'] = gemini_type
```

### Value Parsing

Gemini returns natural language values that must be parsed:

- `"10kΩ"` → `10k`
- `"100 µF"` → `100u`
- `"12V DC"` → `DC 12`
- `"1N4148"` → `1N4148` (model name for diodes)

SPICE-compatible suffixes:
- `k` = kilo (10³)
- `M` = mega (10⁶) or milli (10⁻³) depending on context
- `u` = micro (10⁻⁶)
- `n` = nano (10⁻⁹)
- `p` = pico (10⁻¹²)

## SPICE Formatting

The `stringify_line` method converts structured netlist to SPICE syntax:

```python
def stringify_line(self, line):
    comp_id = line['id']
    terminals = ' '.join(str(t) for t in line['terminals'])
    value = line.get('value', '?')
    
    # Special handling for sources
    if line['class'].startswith('voltage'):
        if 'DC' in value or 'AC' in value:
            return f"{comp_id} {terminals} {value}"
        else:
            return f"{comp_id} {terminals} DC {value}"
    
    # Standard passive components
    return f"{comp_id} {terminals} {value}"
```

### Ground Handling

`gnd` components are mapped to node `0`:

```python
'gnd': '0'  # In netlist_map
```

All ground symbols in the circuit are treated as the same node, establishing the reference potential.

## Netlist Validation

Before final output, the netlist is filtered:

```python
# Remove invalid entries
valid_netlist = [
    line for line in netlist
    if line.get('id') and 
       line.get('terminals') and 
       len(line['terminals']) >= 2
]
```

**Common Invalid Cases:**
- Components with only one terminal (disconnected)
- Missing component IDs
- Duplicate component IDs

<Note>
Disconnected components are logged as warnings but not included in the final netlist, as SPICE requires at least two terminals per element.
</Note>

## Performance Metrics

### Timing Breakdown

| Operation | Time | Notes |
|-----------|------|-------|
| Component Enumeration | 0.2-0.5s | Depends on layout complexity |
| Structural Netlist Generation | 0.1-0.2s | Pure algorithmic |
| Gemini API Call | 2.0-4.0s | Network latency + inference |
| Netlist Fixing | 0.1-0.3s | Value parsing and merging |
| **Total** | **2.4-5.0s** | Dominated by Gemini API |

### Accuracy

- **Component Value Extraction**: ~85-90% accuracy (depends on label clarity)
- **Type Verification**: ~95% agreement with YOLO (Gemini cross-validation)
- **Terminal Ordering**: ~92% correct for polarized components (with VLM directions)

<Info>
Gemini's accuracy improves significantly on high-resolution, clearly labeled diagrams. Hand-drawn or photographed circuits may require manual correction.
</Info>

## Integration with Simulation

The final netlist can be exported and used directly:

1. Copy from Streamlit text editor
2. Paste into SPICE simulator
3. Add analysis directives (`.tran`, `.ac`, `.dc`)
4. Run simulation

Example with analysis directive:
```spice
* CircuitVision Generated Netlist
V1 0 1 DC 12
R1 1 2 10k
R2 2 3 4.7k
C1 3 0 100u

* Analysis
.tran 0 1m 0 1u
.print tran v(1) v(2) v(3)
.END
```
